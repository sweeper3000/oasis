# Oasis

A self-hosted file server with local and external storage, browser previews, and public file links.

[中文 README](README_cn.md) · [MIT license](LICENSE-MIT) · [Third-party acknowledgements](THIRD_PARTY_NOTICES.md)

![Oasis file browser](doc/demo.png)

## Features

- Accounts, administrator settings, optional guest access, and file visibility rules.
- Upload, download, search, folders, ZIP downloads, and copies/moves with live progress, stage, and filename.
- Images, text, PDFs, audio, video, subtitles, and media playlists; supported media formats depend on the browser.
- Public file links generated by the UI expire after six hours.
- External drives using S3-compatible storage, native Backblaze B2, SFTP, FTPS, FTP (insecure), WebDAV, or SMB.
- Optional encryption of remote file contents and names; choose an external main drive or named folders alongside local storage.
- Password-verified database export/restore using encrypted backups and a 12-word recovery phrase. File contents are copied separately.
- English and Chinese interfaces.

## Run this checkout with Docker

From the repository root:

```sh
docker compose -f compose.example.yaml up --build -d
```

Open <http://localhost:8000> and choose `/home/storage` during initial setup.
The example builds `oasis:external-storage-providers` from this source, runs as
UID/GID **10001**, and persists settings and local files in named volumes.
It binds only to the host's loopback interface by default. Copy `.env.example`
to `.env` to customize the host binding or port; uncomment the corresponding
Compose entries before supplying encryption or certificate environment settings.

Existing installations can retain their database and storage bind mounts. Back up
both directories first, preserve the configured storage path, and ensure UID/GID
10001 can read/write both directories before replacing the image. Rebuild and
recreate the container to deploy changes; building an image alone does not replace
an existing container. The source image differs from the older prepared-release
Dockerfile, which does not set a non-root user.

See [Docker Compose and upgrades](doc/external-storage.md#docker-compose) for
bind mounts, encryption keys, private CAs, network access, and temporary disk space.
Do not use `docker compose down --volumes` when retaining named-volume data.

## Build and run without Docker

Use a Node.js version compatible with the frontend lockfile (Node **22** is used
by the source Docker build), npm, and Rust **1.85+** with a native compiler/linker.
The Docker backend build uses Rust 1.90. Run from the repository root:

```sh
node build.js
```

This installs frontend dependencies, builds both applications, and **replaces
`release/`** with a package in `release/oasis/`. Keep runtime data elsewhere.
Run its `oasis` executable (`oasis.exe` on Windows), keeping the adjacent `public/`
directory. Copy `oasis.conf.sample` to `oasis.conf` beside the executable to
customize the listening address, port, or TLS certificates. The default listener
is `0.0.0.0:8000`; visit the server's address and complete setup.

Oasis stores its database in `data/db/` and disposable files in `temp/` beside the
executable. Give its process write access to those locations and to the selected
local storage folder. External storage additionally requires **rclone 1.71+**;
install it on PATH, place it beside Oasis, or set `OASIS_RCLONE` to its executable.
Standalone packages do not bundle rclone.

For local development and checks:

```sh
cd frontend
npm ci
npm run check
npm run build
cd ../backend
cargo test
cargo run
```

The backend serves the integrated application at <http://localhost:8000>.
`npm run dev` separately watches/rebuilds the frontend and starts a static server;
use the backend address for API-dependent behavior. Some filesystem tests require Linux.

## Storage, backups, and playback

Configure providers under **Settings → External storage**. Files are listed directly
from storage; copying files into an accessible local folder does not require UI
uploads or database registration. Storage changes do not migrate existing files.

Remote videos stream through Oasis without a full-file disk download, including
through public links. Other remote responses use a plaintext disk cache that
expires after **24 hours without access**, with no size cap. Cache and temporary
files are cleared at startup; allow sufficient writable disk space even in
external-main-drive mode.

Plyr supplies video controls outside Safari; Safari uses native video controls.
SRT/VTT captions are supported by the player, subject to browser support. Oasis
serves original media without codec conversion or video repair. Seeking requires
valid media timing/index data; changing players cannot recover missing footage.
PDF previews use PDF.js. Public video links can also be used by external players
such as VLC; new requests, including seeks, must occur before link expiry.
